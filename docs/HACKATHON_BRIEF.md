# Colleague Zero — hackathon brief

Source: the Melsoft Academy event page, copied on 27 Oct 2026. Update this file if anything changes at kickoff.

## In one paragraph
Colleague Zero is a 24-hour hackathon run by Melsoft Academy about **multi-agent workflows**. Teams build an autonomous "digital employee" for **education**: a set of AI agents that is given a goal, breaks it into steps, uses tools and data to do the work, checks its own output, fixes its own mistakes and delivers a finished result without a person stepping in. The organisers say clearly that they do not want a chatbot (it only answers questions) or a fixed automation script (it repeats the same steps and breaks when something unexpected happens).

## The reference demo on their page
Four agents (Planner, Marker, Reviewer, Messenger) mark 32 Grade 10 essays against a rubric. The Reviewer notices that essay #14 was given 41% even though it meets two of the rubric criteria and sends it back; the Marker re-marks it at 63% and logs the reason. Feedback then goes to all 32 learners and a summary to the facilitator. The run ends with "Human interventions: 0".
That is the bar: a visible plan, real work, a caught mistake, a logged fix and a delivered result.

## What judges look for — the five-point checklist
1. **Reasons** — breaks a goal into steps and decides what to do next instead of following a script.
2. **Self-corrects** — reviews its own work, catches errors and tries again until the result is right.
3. **Executes** — completes a multi-step workflow and delivers a finished result, not a suggestion.
4. **Collaborates** — more than one agent, each with a clear role, handing work to one another.
5. **Serves education** — solves a specific, real need in teaching, learning or running an education programme.

## How a digital colleague works (their model)
Goal → Plan → Act → Check → Correct → Deliver
- **Goal** — a person states an outcome, not step-by-step instructions.
- **Plan** — a planner agent splits it into steps and assigns them.
- **Act** — worker agents use tools, data and APIs to do each step.
- **Check** — a reviewer agent tests the output against the goal.
- **Correct** — problems go back to be fixed and checked again.
- **Deliver** — the finished work reaches the people who need it.

Three role types: **Planner** (the plan and who does what) · **Workers** (do the steps with tools) · **Reviewer** (checks, flags problems, sends work back).

## Example ideas from the organisers
Any real problem in education is allowed. Their examples: a marking colleague, a curriculum colleague, a learner-support colleague, an admissions colleague and a career colleague.

## Easy to miss
- Code freeze (09:00) is the same time as registration — **push before you leave home**.
- There are two checkpoints on Friday (13:00 pitch and 17:00 demo); plan milestones around them.
- Live demos fail on venue Wi-Fi — bring a hotspot, a replay mode and a recorded video.
- Teams that mix roles (developers, a designer, an educator, a storyteller) are encouraged.
